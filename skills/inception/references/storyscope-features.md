# StoryScope Feature Registry

## Use and limits

This registry translates the 30 core narrative features reported in Tables 14–16 of Russell et al., [“StoryScope: Investigating idiosyncrasies in AI fiction”](https://arxiv.org/abs/2604.03136), into inspection cues for Inception’s fiction audit. The paper’s population-level tendencies are not quality rules. Feature presence cannot prove AI authorship. An AI-elevated value is not a reason to delete it, and a human-elevated value is not a reason to add it.

Do not reverse each feature one by one, optimize toward the human-elevated side, or use this registry as a negative-prompt checklist. A feature can become a Decision Ledger candidate only when the observable choice has enough evidence and creates a material tension with the author’s Intent Contract. Familiar choices that serve the genre, audience, length, point of view, desired effect, or another stated constraint should be kept. This registry is an audit evidence layer, not a new ledger schema.

“Feature space” and “dispersion” are design terms for reasoning about narrative choices. Inception does not calculate embeddings, vector distances, rarity, author identity, or AI probability, and it does not perform authorship classification.

`population_direction` records an inspection prior from the cited study, not a recommendation. The three categorical overlaps—`Reference Explicitness`, `Subplot Integration`, and `Dominant Emotional Expression`—each remain one feature entry with multiple value-level directions. The feature itself is not inherently AI-elevated or human-elevated.

The dimensions use the paper’s NarraBench prefixes:

| Prefix | Dimension |
| --- | --- |
| `AGENT` | Agent |
| `EVT` | Events |
| `PER` | Perspective |
| `PLT` | Plot |
| `REV` | Revelation |
| `SET` | Setting |
| `SIT` | Situatedness |
| `TMP` | Temporal Structure |

Each entry supplies the following fields: `feature_id`, formal English name, StoryScope / NarraBench dimension, definition or diagnostic question, response space or main observation direction, `population_direction`, `evidence_cues`, `false_positive_cautions`, `audit_mode`, and a mapping to the existing fiction diagnostic axes. `audit_mode` is limited to `passage`, `cross_scene`, `whole_story`, and `hybrid`.

The registry ends at 30 unique core feature entries. Feature IDs may support a reviewer’s working notes, but they must not be persisted as new ledger keys. If a feature trace is useful in a ledger, use the existing `observed_choice`, `suspected_default`, `diagnostic_axis`, and `evidence` fields.
